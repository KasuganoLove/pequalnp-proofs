# L-meta-8323 bundle pruning

This directory contains a reproducible source-pruning plan and two subsequent
proof-resource patches for the standalone 8323 bundle. The pruning step changes
neither mathematical statements nor retained proof scripts. The later patches
replace unnecessary finite certificates with smaller direct or symbolic proofs;
they preserve the public theorem statement. These scripts write adjacent
artifacts, not the canonical repository source or frozen modular sources.

## Analysis

`Analyze8323.lean` imports the compiled **unpruned** canonical module and records
its own-module constants, compiler declaration ranges, and dependencies in
`dependencies.json`. It uses `ConstantInfo.getUsedConstantsAsSet`, the same
dependency primitive as the project's checker. Constants are selected by their
defining module, so private/generated constants are included.

`prune_bundle.py` consumes the preserved source and that JSON. It verifies the
input hash, keeps the final theorem's complete local dependency closure, and
maps generated constants to their nearest source declaration ancestor. Lean's
private-name prefix is removed before resolving the source owner. It additionally
retains all dependencies of every constant generated by a retained command and
all local declarations matching identifiers in retained proof source; ambiguous
namespace suffixes retain every matching candidate. Both instances are retained.

Only compiler-ranged declaration commands and directly attached `set_option ...
in` / `open ... in` wrappers can be deleted. Namespace, section, and other ambient
commands are preserved. The script refuses unexpected nested declaration ranges
or local inductive/structure/mutual declarations rather than assuming they can
be split safely. The inspected source contains none of those special commands.

The assertions verify that every required constant has a source owner, no such
owner is removed, and all local dependencies of retained commands have retained
owners. Details, ranges and reasons are in `pruning-report.json`.

## Reproduction and verification boundary

With the preserved source and JSON present, run:

```sh
python prune_bundle.py
python finalize_bundle.py slim-L_meta_8323.lean finalization.json
python resource_patch.py
python symbolic_patch.py
```

These commands are independent of the original workspace path. The pruner
verifies the unpruned source hash. The finalizer verifies both the slim input hash
and the attributed output hash, then writes only
`finalized-L_meta_8323.lean` beside its script. It never writes to the repository's
canonical module path.

`resource_patch.py` requires the attributed input hash above, deletes the full
`Sym2` edgeFinset-cardinality certificate, and proves graph nonemptiness directly
with the edge between vertices 0 and 21. The separately checked research source
is archived as `../lean/Pnp4201EdgeWitness.lean` with its ordinary log under
`../validation/EdgeWitness-lean.log`.

`symbolic_patch.py` requires the direct-edge input hash and the exact
`Pnp4201SymbolicAdj.lean` proof-source hash
`9d0a683e9a057b2f299480dd1e01e817a9aca1f824f2e5aedd9fca6c18ca235a`.
It replaces three exhaustive adjacency-table certificates by their checked
arithmetic proofs and adds the `point_ne_line` separation helper used by those
proofs. The proof source is included beside the script and under `../lean/`;
its ordinary log is `../validation/SymbolicAdj-lean.log`. Both patch scripts
emit their output and a report in this directory. Their hashes distinguish
proof-resource revisions; they are not hashes of different public statements.

The symbolic version is slightly longer as source text while replacing finite
proof certificates. No strict-check success or memory-use improvement is inferred
from source size, ordinary compilation, or these patch reports. Root records
strict-check attempts separately, including resource failures.

To regenerate `dependencies.json`, use an isolated checkout with the project's
pinned toolchain, Mathlib, and unchanged definitions. Set `PNP8323_ARCHIVE` to the
absolute path of this directory, then run from that checkout's `lean/` directory:

```sh
PNP8323_ARCHIVE=/absolute/path/to/bundle-pruning
cp "$PNP8323_ARCHIVE/unpruned-L_meta_8323.lean" PEqualNP/Outside/L_meta_8323.lean
lake env lean -j1 -o .lake/build/lib/lean/PEqualNP/Outside/L_meta_8323.olean PEqualNP/Outside/L_meta_8323.lean
PNP8323_DEPENDENCIES_OUT="$PNP8323_ARCHIVE/dependencies.json" lake env lean -j1 "$PNP8323_ARCHIVE/Analyze8323.lean"
```

`Analyze8323.lean` reads `PNP8323_DEPENDENCIES_OUT`, defaulting to
`dependencies.json` in the process working directory. Its recorded successful
run reported 994 module constants, 430 constants with source ranges, and 593
constants in the final theorem closure. The destination was made portable after
that run; the extraction algorithm and saved data were unchanged.

Use the **unpruned** source under the original module name for this analysis.
Do not analyze a differently compiled source against the preserved line ranges.

The source-pruning assertions are not a substitute for Lean elaboration or the
project checker. Root owns copying the candidate to the canonical path, adding
attribution after range pruning, rebuilding it, and running the strict checker.
No strict checker was run by the pruning agent.

Retain the existing source attribution when publishing: upstream L_meta_1501
and L_meta_2235; erasure helpers via L_meta_2668 / L-meta-1499 / PR3112; constant
propagation via L_meta_1680 and L_meta_1425. The repository is Apache-2.0.
