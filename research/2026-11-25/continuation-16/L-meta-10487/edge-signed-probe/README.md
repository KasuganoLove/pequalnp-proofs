# L-meta-10487: smaller signed-search sample set

This checkpoint tests a possible reduction of the numerical certificate size
for positive twin L-meta-10486. It does not change the public target function.
No Lean build, strict checker, or official submission was run by this worker
for this checkpoint.

## Samples and implication

The search uses all fifteen edge assignments as positive examples and all
fourteen negative assignments of the seven-variable graph. The 29 distinct
assignments are packed in ascending positive order followed by ascending
negative order. `problem.json` contains their exact values, the fifteen
graph edges, raw-column masks, and essential-variable witnesses.

Every circuit computing the full graph function must satisfy these samples.
Consequently, a proved lower bound for this partial function would also be a
lower bound for the full function. This implication does not assume the
candidate circuit is monotone. A circuit fitting the samples alone would not
necessarily compute the full function.

The complete positive/negative Cartesian product has 210 pairs, corresponding
to a 420-bit paired encoding in the existing Lean checker, compared with the
earlier 3,192-bit full-domain encoding. All seven raw inputs remain necessary:
for each raw input a sampled positive and a sampled negative differ only at
that input. Direct enumeration of all 128 initial raw-input sublists confirms
that only the full sublist passes separation.

Lean proof or a separately verified UNSAT certificate.

The optimized search's process record reports peak RSS 98,560 KiB. The literal
program reports its own peak RSS as 6,640 KiB. Its wrapper record reports
172,952 KiB for child processes; that invocation followed compilation in the
same shell, so this larger envelope must not be attributed solely to the
search executable.

The optimized engine preserves the previously reviewed signed live-wire
algorithm, with its complement now defined by XOR with `(1 << 29) - 1`.
The literal engine uses no memoization, sorting, polarity canonicalization,
constant skipping, or duplicate skipping. Its only representation change is
using masked 32-bit words for the 29 truth-table columns.

## Independent finite-data audit

`independent-sample-audit.py` recomputes the public graph's truth table, sample
labels, all 210 paired labels, all 420 packed bits, every raw-input sublist,
and first-level valid successor states. The saved audit passes. These checks
do not run the recursive search and do not certify its negative result.

The smaller sample set permits **108** first-level successors, including 84
retaining both selected operands, 12 retaining the first, and 12 retaining the
second. Old 88-child branch data from the full-domain instance must not be
reused for this instance. The exact new ordered list is preserved in
`independent-first-level-420.json` and is regenerated by the audit script.

## Reproduction

From this directory, build into a separate output directory to preserve the
recorded results:

```sh
mkdir -p reproduction
c++ -std=c++20 -O3 probe.cpp -o reproduction/probe
c++ -std=c++20 -O3 literal-probe.cpp -o reproduction/literal-probe
(ulimit -v 1048576; ./reproduction/probe 10487 10 60) > reproduction/optimized-result.json 2> reproduction/optimized-stderr.log
(ulimit -v 1048576; ./reproduction/literal-probe) > reproduction/literal-result.json 2> reproduction/literal-stderr.log
```

The runtime wrapper `run.py` is retained with the exact timing/resource
records. Running it in place overwrites the selected recorded output.
Compiled binaries are excluded from the curated manifest.
